Architecture + Compose + API Contract

Single-page reference to discuss implementation details before coding: topology, Docker Compose service map, and initial API/data contracts for events and A/B parser experiment logs.

Core Services

bot (Baileys intake), api (event lifecycle), display (carousel web app), db (SQLite/Postgres).

Parsing Modes

Variant A: deterministic rules. Variant B: LLM structured extraction with schema validation and fallback.

Deployment Targets

Compose first on local machine, then same topology ported to Raspberry Pi with ARM-ready images.

2) Suggested Docker Compose Service Map

Service Image/Build Ports Volumes Main Env Vars
bot Node app (./services/bot) - wa_auth:/app/auth WA_GROUP_JID, PARSER_SPLIT_MODE, API_BASE_URL
api Node app (./services/api) 8080:8080 events_data:/app/data DATABASE_URL, LLM_API_KEY, AB_ASSIGNMENT_MODE
display Static app (./services/display) 3000:3000 - PUBLIC_API_URL, CAROUSEL_INTERVAL_MS
db (optional if Postgres) postgres:16-alpine 5432:5432 pg_data:/var/lib/postgresql/data POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD
watchtower (optional) containrrr/watchtower - /var/run/docker.sock WATCHTOWER_POLL_INTERVAL

Start with SQLite in api for easiest local bring-up. Move to Postgres when you need concurrent writers, analytics, or backups.

3) Initial API Contract

Endpoint Method Purpose Notes
/health GET Service health Used by Compose health checks
/events GET List upcoming events For display carousel
/events POST Create canonical event Called after parser + validation
/events/:id/publish POST Publish event message to group Manual retry path
/experiments/parses POST Store A/B parse run Input text, variant, metrics, outcome
/experiments/metrics GET Aggregated parser stats Success rate, p95 latency, cost
