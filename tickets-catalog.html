Epic A - Platform & Repository Setup

EVT-001 - Initialize repository structure for bot, api, display, and shared packages

Epic APlatformSize: SHigh

Create a predictable mono-structure to avoid coupling and make Docker builds straightforward.

  • Each service has its own README and startup command.
  • Shared package exports event schema types.

EVT-002 - Create docker-compose baseline for local development

Epic ADevOpsSize: MHigh

Define one-command local startup for full stack validation.

  • docker compose up starts bot, api, display, and storage dependencies.
  • Named volumes declared for WhatsApp auth and DB persistence.
  • Healthchecks configured for API and display services.

EVT-003 - Add environment config templates and validation

Epic AConfigSize: SHigh

Prevent runtime crashes from missing secrets or invalid config.

  • Create .env.example with all required keys and comments.

  • Support split mode toggles for A/B parser assignment.

EVT-004 - Implement Baileys authentication and reconnect lifecycle

Epic BBotSize: MHigh

Keep bot session durable across restarts and temporary disconnects.

  • Session credentials persist to volume-backed path.
  • Reconnect logic handles recoverable disconnect reasons.
  • Connection state transitions are logged with request identifiers.

EVT-005 - DM-only message filter and sender allow-list

Epic BBotSize: SHigh

Restrict intake to intended users and avoid accidental group ingestion loops.

  • Only private chat messages enter parse pipeline.
  • Optional allow-list mode blocks unknown senders.
  • Rejected messages are logged with reason and sender hash.

EVT-006 - Build idempotent message intake record

Epic BReliabilitySize: MHigh

Ensure duplicate events are not created when WhatsApp retries or restarts occur.

  • Store unique key using sender JID + message ID.
  • Duplicate payloads are no-op and acknowledged in logs.
  • Raw text is stored temporarily for parser debugging.

Epic C - Parsing A/B Engine

EVT-007 - Implement parser A (rule-based extraction)

Epic CParser ASize: MHigh

Create deterministic extraction for title/date/time/location with confidence score.

  • Regex rules cover at least 10 common message formats.
  • Date parsing handles locale ambiguity and timezone defaults.
  • Output shape matches canonical event schema.

EVT-008 - Implement parser B (LLM structured output)

Epic CParser BSize: LHigh

Use LLM API with strict JSON response contract and robust error handling.

  • Prompt includes schema, examples, and invalid output guardrails.
  • On malformed output, one retry is attempted before fallback.
  • Token usage and latency are captured in experiment logs.

EVT-009 - Build A/B router (random and sender-sticky modes)

Epic CExperimentSize: MHigh

Assign each DM to parser variant A or B based on runtime strategy.

  • Supports random_50_50 and sender_sticky assignment.
  • Assignment is included in parse log payload.
  • Mode can be changed by env var without code changes.

EVT-010 - Parse quality evaluator and confidence thresholds

Epic CQualitySize: MMedium

Normalize parse quality scoring and determine confirmation requirements.

  • Defines thresholds for auto-publish, confirm-needed, and reject.
  • Tracks required field coverage and parser-specific errors.
  • Provides single confidence output regardless of parser variant.
